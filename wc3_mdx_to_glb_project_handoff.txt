HISTORY OF THE MAIN TECHNICAL FIXES

A. ANIMATION EXPORT

Original symptom: - Exported GLBs had no usable animations in Blender.

Root cause found in the newer converter: - It treated animation tracks
as indexed arrays and expected fields like Frame and Values. - The
actual war3-model data structure uses AnimVector.Keys. Each key contains
Frame and Vector. - The newer code also omitted scaling tracks. - The
glTF Transform API usage needed to follow the current
createAnimationSampler()/createAnimationChannel() pattern, with target
node/path and sampler assigned correctly.

Fix implemented: - Read Translation.Keys, Rotation.Keys, and
Scaling.Keys. - Read each key’s Frame and Vector. - Create glTF
animation samplers/channels using the current API. - Export clips and
report channel counts.

Observed result: - User confirmed that many MDX animations now export
and appear in Blender Dope Sheet/NLA. - HumanPriest and Grunt animations
such as Stand, spell cast, Death, Walk, Attack -1, and Stand Victory
were reported to animate correctly.

Known limitations / warnings: - Global-sequence tracks are currently
skipped or not fully handled. - Hermite/Bezier interpolation is
approximated as LINEAR. - These warnings are not necessarily blockers
for the current WC2 Grunt texture investigation, but they remain
correctness work for full-fidelity animation conversion.

B. SKELETON / BIND POSE

Original symptoms: - HumanPriest had poor shoulder/arm placement or arms
floating behind the body in the initial load pose. - The Grunt initially
appeared as a tangled/meatball collection of limbs until the armature
was removed. - Animation could play, but the default/bind pose and
skinning were not consistently correct.

Problems identified in the earlier converter: - Nodes were initialized
with identity transforms without correctly accounting for Warcraft III
PivotPoints. - Inverse bind matrices were initialized as identity, which
is not correct for a real skinned model. - Skin groups that could not be
resolved could silently fall back to joint zero, hiding bad mappings.

Fixes attempted: - Pivot-aware hierarchy / node transform handling. -
More appropriate inverse bind matrix construction. - Diagnostics for
unresolved skin groups and joint mappings.

Observed result: - HumanPriest’s load pose became correct; Stand,
spell-casting, and Death animations looked natural. - Grunt loaded in a
sensible pose and Walk, Attack -1, and Stand Victory were reported as
working. - User confirmed that the models and their visible
particles/spheres were present after this stage.

Status: - Treat skeleton work as substantially improved, not as
mathematically proven for every Warcraft III model. Keep regression
tests when changing shared geometry/material code.

C. MATERIALS AND TEXTURES

Original symptoms: - HumanPriest head was black or transparent, and robe
texture sampling looked wrong. - Grunt’s green flesh color appeared
across armor, horns, and axe; face texture seemed to be applied to
unrelated surfaces. - Earlier exports had missing textures or
fallback/untextured materials.

Problems investigated: - A texture conversion helper (blpToPngBuffer())
had been omitted in one intermediate script, causing texture conversion
failures/null texture slots. Restoring it brought textures back, though
not necessarily onto the correct surfaces. - An early implementation
considered only TVertices[0]. MDX materials/layers can use CoordId and
multiple texture-coordinate sets. However, the tested Grunt geosets
reported UV sets=[0], so multiple UV sets are not currently the leading
explanation for this particular Grunt issue. - Warcraft III materials
can contain multiple layers, different filter modes, animated alpha, and
replaceable texture IDs. Treating each layer as an independent full
geometry pass can duplicate geosets and is not a faithful general
solution. - Animated alpha is represented by animation tracks, not
always a constant number. A first alpha key of 0 must not be interpreted
as permanently transparent. - ReplaceableId 1 is TeamColor;
ReplaceableId 2 is TeamGlow. - Texture lookup previously used unsafe
global basename fallback. That could select an unrelated file with the
same basename from another campaign/UI folder.

Material diagnostic observations: - A base-layer-only diagnostic export
looked essentially identical to the previous export in the user’s test,
so that switch did not isolate the problem. - Some material layers
reference Shockwave_Ice1.blp, which was absent in the small tester
folder. - Some layers use Grunt.blp and gutz.blp. - A material also uses
ReplaceableId 1 (TeamColor). - Animated alpha tracks were observed on
multiple layers. - Filter modes including values 2 and 4 were observed;
their exact mapping/behavior needs to be validated against MDX semantics
and glTF material behavior.

Important caution: - Do not assume every material layer should be
exported as a separate duplicated mesh. - Do not assume an unresolved
texture is the cause of face UV misalignment until the affected
geoset/material is identified. - Do not use a broad fuzzy match
silently. A wrong match can look plausible while corrupting other
models.
